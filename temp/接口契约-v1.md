# 新源村情通 · V1 接口契约

> 版本：v1.0 ｜ 状态：**V1 已冻结（只增不改）** ｜ 适用：小程序端、后端、Mock 服务
>
> 本文是前后端分离的唯一接口依据。V1 已实现前端与 Mock；真实后端按本文实现即可直接替换。
> 路径统一前缀 `/api/v1`，破坏性变更必须新开 `/api/v2`。

---

## 1. 通用约定

### 1.1 地址与环境

| 环境 | Base URL | 说明 |
|---|---|---|
| 本地 Mock | `http://127.0.0.1:3000/api/v1` | `temp/mock-server` |
| 开发 | `https://dev-api.xinyuan-village.cn/api/v1` | 待部署 |
| 生产 | `https://api.xinyuan-village.cn/api/v1` | 需 HTTPS + 备案域名 |

小程序端切换开关：`cilent/utils/config.js` 中 `USE_MOCK`。

### 1.2 请求头

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 受保护接口必填 | `Bearer {token}` |
| `Content-Type` | POST/PUT | `application/json` |
| `X-Client` | 是 | 固定 `wx-miniprogram` |
| `X-Client-Version` | 是 | 如 `1.0.0`，用于灰度与埋点 |

### 1.3 统一响应

所有 JSON 接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "a1b2c3d4e5f6",
  "timestamp": 1763095200000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 成功；非 0 见错误码 |
| `message` | string | 面向用户的可读提示，前端可直接展示 |
| `data` | any | 业务数据；失败时一般为 `null` |
| `traceId` | string | 链路 ID，前端错误页可展示后 8 位 |
| `timestamp` | long | 服务端毫秒时间戳 |

### 1.4 错误码

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `20001` | 401 | 未登录 / token 过期 | 清 token，引导登录 |
| `20002` | 403 | 无权限（角色不足） | 提示“当前身份暂不能办理” |
| `20003` | 200 | 手机号或密码不正确 | 展示「账号或密码错误」，停在登录页 |
| `40001` | 200 | 参数不合法 | 展示 `message`，定位到字段 |
| `40004` | 200 | 能力未开放（V3 / 支付预留） | 展示“将在对应版本开放” |
| `40401` | 200 | 文章不存在/已下线 | 空态 + 返回列表 |
| `40402` | 200 | 事项不存在/已下线 | 空态 + 返回列表 |
| `42901` | 429 | 请求过于频繁 | 提示稍后再试 |
| `50000` | 500 | 服务内部错误 | 错误态 + 重试 |
| `50001` | 504 | 上游超时（AI/支付） | 降级 + 重试 |

### 1.5 分页

请求：`page` 从 1 开始，`pageSize` 默认 10、最大 50。  
响应：

```json
{
  "list": [],
  "total": 26,
  "page": 1,
  "pageSize": 10,
  "hasMore": true
}
```

### 1.6 时间与 ID

- 时间统一 `yyyy-MM-dd HH:mm:ss`（东八区），前端负责格式化为“今天/昨天/11-12”。
- 业务主键用字符串，避免 JS 精度问题（后端可用雪花 ID 转字符串）。
- 金额单位：**分**（V1 只读展示除外，直接给 `380` 表示元；V2 支付接口统一用分）。

### 1.7 契约不变式

1. 路径不重命名，只新增；
2. `Result` 五字段壳不变；
3. 枚举只增，旧值语义不变；前端对未知值兜底显示；
4. 表只加字段，不删列、不改语义。

## 2. 认证

### 2.1 微信静默登录

`POST /auth/wx-login`

```json
{ "code": "wx.login 返回的 code", "regionId": "65402510001" }
```

响应：

```json
{
  "token": "eyJhbGciOi...",
  "tokenType": "Bearer",
  "expiresIn": 604800,
  "isNewUser": false,
  "user": {
    "id": "u1001",
    "name": "王秀兰",
    "roleCode": "villager",
    "roleName": "村民",
    "phoneDisplay": "138****6621",
    "avatarText": "王",
    "regionId": "65402510001",
    "regionName": "新源村",
    "gridName": "第三网格",
    "regionPath": ["新源县", "城关镇", "新源村"]
  }
}
```

要点：

- 后端用 `code2Session` 换 `openid`，不返回 `session_key`；
- 首次登录自动建档，`roleCode` 默认 `villager`；
- token 建议 JWT + Redis 白名单，`expiresIn` 7 天；
- `regionId` 用于确定默认村，不允许前端伪造跨村数据权限。

### 2.2 开发态模拟登录

`POST /auth/mock-login`（**仅 dev profile 存在；prod 返回 404**）

请求：`{ "regionId": "65402510001" }`  
响应：同 `wx-login`，直接返回种子用户 `王秀兰`。

### 2.3 退出登录

`POST /auth/logout`

响应：`data: true`。服务端将 token 加入 Redis 黑名单直至自然过期。

### 2.4 账号密码登录（2026-11 新增）

`POST /auth/password-login`

个人中心「账号密码」页签使用。适用于不方便走微信授权的场景（如演示账号、村委工作机）。

请求：

```json
{ "account": "13843216621", "password": "123456" }
```

响应：与 `wx-login` 完全一致（`token / tokenType / expiresIn / isNewUser / user`）。

```json
{
  "token": "eyJhbGciOi...",
  "tokenType": "Bearer",
  "expiresIn": 604800,
  "isNewUser": false,
  "user": {
    "id": "u1001",
    "name": "王秀兰",
    "phone": "13843216621",
    "phoneDisplay": "138****6621",
    "roleCode": "villager",
    "roleName": "村民",
    "regionId": "22022110001",
    "regionPath": ["永吉县", "口前镇", "新源村"]
  }
}
```

规则：

- `account` 为手机号；`password` 至少 6 位；
- 后端保存 **BCrypt** 哈希，不存明文；
- 账号或密码错误返回 `code=20003`、HTTP 200，`message` 固定为「手机号或密码不正确」，避免暴露账号是否存在；
- 同一账号 10 分钟内连续失败 5 次返回 `42901`；
- 演示账号：`13843216621 / 123456`（登录页已提示，仅演示环境有效）。

## 6. AI 网格员

> **2026-11 更新**：AI 答案可由「大模型 + RAG」生成，`refs` 为检索到的文章/事项；未配置模型或调用失败时自动回退规则引擎。
> SSE 事件顺序、字段与下方契约完全一致，前端无需改动。

### 6.1 推荐问题

`GET /ai/suggestions`

```json
{
  "list": [
    { "id": "s1", "text": "今年医保怎么缴？" },
    { "id": "s2", "text": "独生子女证需要什么材料？" }
  ],
  "welcome": "您好，我是新源村 AI 网格员“小贾”……",
  "disclaimer": "AI 生成内容仅供参考，具体政策以官方发布为准。"
}
```

### 6.2 流式对话（SSE）

`POST /ai/chat/stream`

请求头必须包含 `Accept: text/event-stream`。请求体：

```json
{
  "question": "今年医保怎么缴",
  "conversationId": "cv_20261114_001"
}
```

`conversationId` 为空时由服务端创建，并在 `meta` 事件返回。

响应事件顺序：`meta` → `delta`×N → `refs` → `done`；异常时 `error`。

```text
event: meta
data: {"conversationId":"cv_001","messageId":"m_001","intent":"medical","needRefs":true}

event: delta
data: {"text":"今年"}

event: delta
data: {"text":"城乡居民医保"}

event: refs
data: {"refs":[{"type":"article","id":"a1001","articleId":"a1001","title":"关于2026年度城乡居民基本医疗保险集中缴费的通知","source":"新源村党群服务中心","snippet":"个人缴费380元/人·年","route":"/pages/article/detail?id=a1001"}]}

event: done
data: {"conversationId":"cv_001","messageId":"m_001","latencyMs":1260,"followUps":["帮老人代缴要带什么？","医保报销比例是多少？"]}
```

错误：

```text
event: error
data: {"code":50000,"message":"AI 服务暂时不可用，请稍后重试"}
```

实现要求：

- `Content-Type: text/event-stream; charset=utf-8`；
- `Cache-Control: no-cache`、`X-Accel-Buffering: no`；
- 首字（第一个 `delta`）P95 < 3s；
- 客户端断开后服务端必须停止生成，释放模型连接；
- 回答必须先结构化事项、再知识库、最后兜底，**不允许编造金额/时限**；
- 每个 `delta` 的文本不能拆开 UTF-8 字符（按字符而不是字节切）。

### 6.4 消息反馈

`POST /ai/messages/{messageId}/feedback`

```json
{ "feedback": "up" }
```

`feedback`：`up` / `down`。响应 `{ "messageId": "m_001", "feedback": "up" }`。点踩进入“知识盲区”队列（V3 运营闭环）。

### 6.5 会话历史

- `GET /ai/conversations?page=1&pageSize=20` → 会话列表；
- `GET /ai/conversations/{id}/messages` → 消息明细；
- `DELETE /ai/conversations/{id}` → 删除会话。

V1 前端暂以本地存储兜底；后端按此实现即可开启历史页。

| `POST` | `/gov/applies/{id}/pay` | 在线缴费（V2.1，微信支付） |

> 按你的要求，**不提供管理端 `/admin/*` 接口**。V2 演示阶段办件状态由种子数据/脚本推进；等以后真需要后台时再单独补，不影响这组村民端接口。
