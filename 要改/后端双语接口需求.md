# 后端双语接口需求（延边 · 中文 / 朝鲜语）

> 前端已完成语言切换入口：个人中心 → 便民服务 → 语言设置。
> 前端不修改后端代码；以下为后端需要补充的接口、字段和验收要求。
> 语言代码：`zh`（简体中文）、`ko`（朝鲜语，延边当地用法）。

## 1. 语言传递方式

所有面向用户的接口都接受以下任一种方式：

```http
X-Lang: ko
```

或查询参数：

```text
?lang=ko
```

优先级：`X-Lang` > `lang` > 用户默认语言（`zh`）。

未传或非法值时按 `zh` 返回，不能报错。

## 2. 统一返回结构

建议不改变现有字段，新增 `i18n` 对象：

```json
{
  "id": "a1001",
  "title": "关于2026年度城乡居民基本医疗保险集中缴费的通知",
  "summary": "个人缴费380元/人·年……",
  "i18n": {
    "ko": {
      "title": "2026년도 도시·농촌 주민 기본의료보험 집중 납부 통지",
      "summary": "1인당 380위안……",
      "content": "<p>……</p>"
    }
  }
}
```

列表接口同样在每条数据上返回 `i18n.ko`；不要只返回一个整包翻译。

## 3. 需要双语的接口

### 3.1 首页与资讯

```text
GET /home?lang=ko
GET /articles?lang=ko
GET /articles/{id}?lang=ko
GET /columns?lang=ko
```

需要双语字段：

- 村庄名称、网格名称；
- 通知 `text`；
- 横幅 `tag/title/titleHighlight/subtitle/meta/actionText`；
- 栏目 `name/description`；
- 资讯 `title/summary/content`（富文本保留 HTML，图片不变）；
- 页脚、热线说明。

### 3.2 政务服务

```text
GET /gov/categories?lang=ko
GET /gov/items?lang=ko
GET /gov/items/{code}?lang=ko
GET /gov/applies?lang=ko
GET /gov/applies/{id}?lang=ko
```

需要双语字段：

- 分类 `name/description`；
- 事项 `name/shortName/summary`；
- 办理条件 `conditions[]`；
- 材料 `materials[].name/note`；
- 表单 `formFields[].label/placeholder/options[]`；
- 收费、时限、窗口、电话说明；
- 办件状态、时间轴 `logs[].label/note`；
- 评价文案。

### 3.3 诉求与管理员工作台

```text
GET /requests?lang=ko
GET /requests/{id}?lang=ko
GET /workbench/summary?lang=ko
GET /workbench/requests?lang=ko
GET /workbench/requests/{id}?lang=ko
GET /workbench/notices?lang=ko
GET /workbench/statistics/household?lang=ko
```

需要双语字段：

- 诉求类型、状态、时间轴、回复中的**系统文案**；
- 工作台指标名称；
- 通知 `text/type`；
- 户籍统计的网格名、年龄段、户类别。

说明：村民自己填写的诉求标题、内容、姓名、电话属于用户内容，**不要求自动翻译**，原样返回；前端会按原文显示。

### 3.4 便民服务

```text
GET /directory?lang=ko
GET /jobs?lang=ko
GET /tea-meetings?lang=ko
```

需要双语字段：

- 服务分类、服务名称、说明、营业时间；
- 岗位 `title/company/desc/tags/location`；
- 奶茶会 `title/location/host/summary/agenda[]/status`。

### 3.5 用户与系统

```text
GET /users/me?lang=ko
GET /app/config?lang=ko
```

需要双语字段：

- `roleName`（村民/管理员）；
- `regionPath`（永吉县/口前镇/新源村，或延边当地行政区划）；
- `gridName`、`houseName`、`gridWorker.duty`；
- 页脚、免责声明、AI 欢迎语；
- 字典表 `applyStatus/requestStatus/materialStatus` 的 `label`。

## 4. 错误与提示

所有 `Result.message` 需要按 `X-Lang` 返回：

```json
{ "code": 20003, "message": "휴대폰 번호 또는 비밀번호가 올바르지 않습니다." }
```

至少覆盖：

- 登录失败、未登录、无权限；
- 参数校验、文件上传失败；
- 重复提交、状态不允许；
- AI 服务不可用。

## 5. AI 双语

```http
POST /ai/chat
POST /ai/chat/stream
POST /ai/messages/{id}/feedback
GET  /ai/suggestions?lang=ko
```

要求：

- 接收 `lang`，系统提示词要求用朝鲜语回答；
- RAG 检索结果用朝鲜语字段；
- 引用来源标题用朝鲜语；
- 查不到时用朝鲜语说明，并给出村部电话；
- 推荐问返回朝鲜语；
- 流式事件结构不变，只改变 `delta.text` 内容。

## 6. 数据库实现建议

优先使用独立翻译表，避免主表字段爆炸：

```sql
cms_article_i18n(article_id, lang, title, summary, content)
gov_item_i18n(item_id, lang, name, short_name, summary, conditions_json, materials_json, form_json)
cms_notice_i18n(notice_id, lang, text)
biz_directory_i18n(directory_id, lang, name, description, hours)
biz_job_i18n(job_id, lang, title, company, description, tags_json, location)
biz_tea_meeting_i18n(meeting_id, lang, title, location, host, summary, agenda_json)
sys_dict_i18n(dict_type, dict_value, lang, label)
```

说明：

- `lang` 用 `zh`/`ko`；
- 查询时按 `lang` left join，缺失翻译回退中文；
- 资讯正文只翻译文字，不翻译 HTML 标签和图片地址；
- 用户生成内容不写入翻译表。

## 7. 前端约定

前端已经预留：

- `X-Lang` 请求头；
- `lang` 查询参数；
- 语言持久化键 `xct_lang`；
- 语言切换入口：个人中心 → 便民服务 → 语言设置；
- 前端在缺少 `i18n.ko` 时回退中文，不白屏。

## 8. 验收

1. `X-Lang: zh` 返回与当前一致，不能回归；
2. `X-Lang: ko` 时首页、资讯、政务、诉求、便民服务、AI 均为朝鲜语；
3. 缺少某条翻译时回退中文，不报错；
4. 用户填写的内容不被机器翻译覆盖；
5. 列表分页、状态筛选、时间轴顺序不变；
6. AI 流式回答在 `ko` 下为朝鲜语，引用标题为朝鲜语；
7. 管理员工作台在 `ko` 下可用；
8. 自动化测试至少覆盖：首页、资讯详情、政务事项、诉求详情、AI 同步/流式、语言回退。

## 9. 需要后端同学确认

- 翻译内容由谁提供（人工/翻译公司/AI 初翻+人工校对）；
- 是否使用独立翻译表，还是主表加 `_ko` 字段；
- `X-Lang` 是否允许匿名请求；
- 管理端是否需要单独的语言设置；
- 延边当地行政区划、机构名称的官方朝鲜语写法。
