# 后端图片字段需求（通知配图 / 诉求回复图片）

> 前端已在管理员端预留图片选择位：发布通知、回复诉求各最多 3 张。
> 当前前端只做本地预览，**不上传、不提交**；后端补齐字段和接口后，前端再开始传 `images`。
> 数据库字段本机已预留，见 `db/migrations/V3.1-image-fields.sql`。

## 1. 数据库字段

### cms_notice

```sql
images JSON DEFAULT NULL COMMENT '图片 URL 数组（预留，最多 3 张）'
```

### biz_request_reply

```sql
images JSON DEFAULT NULL COMMENT '图片 URL 数组（预留，最多 3 张）'
```

已有库执行一次：

```powershell
mysql -uroot -p123456 --default-character-set=utf8mb4 xinyuan_village -e "source db/migrations/V3.1-image-fields.sql"
```

用最新 `db/schema.sql` 重建库则跳过。

## 2. 字段格式

统一存 URL 字符串数组：

```json
[
  "http://<host>:8080/static/upload/20261115/notice-1.jpg",
  "http://<host>:8080/static/upload/20261115/notice-2.jpg"
]
```

- 不存 multipart，不存 base64；
- 图片先走 `POST /files` 上传，拿 URL 再存数组；
- 空数组或 `null` 表示无图；
- 前端限制：最多 3 张，单张 5MB，jpg/png/webp。

## 3. 需要后端改的接口

### POST /workbench/notices

```json
{ "text": "...", "type": "urgent|normal", "images": ["url1", "url2"] }
```

### PUT /workbench/notices/{id}

同样接收 `images`，允许只传部分字段。

### GET /workbench/notices

每条通知返回：

```json
{ "id": "n1", "text": "...", "type": "normal", "images": ["url1"] }
```

### POST /workbench/requests/{id}/reply

```json
{ "content": "...", "images": ["url1"] }
```

### GET /workbench/requests/{id}

`replies[]` 每条返回 `images`。

### GET /requests/{id}（居民端）

`replies[]` 同步返回 `images`，居民端详情直接展示。

### GET /home

通知条 `notice` 需要返回 `images`，首页才能显示配图。

## 4. 兼容要求

- 旧数据 `images` 为 `NULL`，接口不能报错；
- `images` 非法 JSON 时按空数组处理；
- 不做图片压缩、裁剪，原图 URL 直存；
- 数量超过 3 张时后端截断或报 40001，前端已限制不会超。

## 5. 前端当前状态

- 通知、回复图片：`wx.chooseMedia` 选择，最多 3 张，本地预览、可删除；
- 保存时不传 `images`；
- 后端补完上述字段与接口后，前端只需把 `images` 加进请求体。

## 6. 验收

- 两个 `images` 列存在；
- 发布带图通知后，居民首页通知条能显示配图；
- 回复带图后，居民诉求详情能看到图片；
- 无图通知、无图回复显示正常；
- 旧数据兼容，列表与详情不报错。
